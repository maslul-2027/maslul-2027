# שרת בדיקה פרטי (Issue #43) — כניסה בטלפון + PIN, אישור מנהל, הרשאות בצד שרת

**סטטוס: סביבת TEST בלבד, נתונים סינתטיים בלבד. לא מאושר לנתונים אמיתיים, לא פריסה מבצעית.**

## איך מריצים
```

MASLUL_SEED_ADMIN_PHONE=05XXXXXXXX MASLUL_SEED_ADMIN_PIN=<4 ספרות לא פשוטות> node backend_next/test_server.js
# → https://localhost:8443 (תעודה עצמית; סודות מקומיים נוצרים ב-.test-server/ בהרשאות 0600 ולא נכנסים ל-git)
```
המנהל הראשון נוצר פעם אחת בלבד (bootstrap) כשאין משתמשים; כל השאר נרשמים במסך הכניסה וממתינים לאישור מנהל.

## מה בנוי ונבדק (ראיות: `tests/secure_test_server.js` 28 בדיקות, `scripts/e2e_secure_browser.js` 14 בדיקות)
- **TLS אמיתי** (HTTP גלוי לא מוגש), עוגיית `__Host-` HttpOnly/Secure/SameSite=Strict, CSRF (Origin מדויק + טוקן), כותרות אבטחה/CSP, בלי Service Worker.
- **הרשמה → בקשה ממתינה → אישור מנהל חד-פעמי** (תפקיד: מנהל / מפקד / צפייה בלבד; קורס; ואופציונלית צוות/מחלקה). משתמש ממתין לא נכנס. PIN חלש נדחה. נעילה אחרי כשלונות, הגבלת קצב, ללא חשיפת קיום משתמש.
- **אכיפה בצד שרת:** הזהות והתפקיד נלקחים רק מה-session. מפקד צוות רואה/כותב רק בצוות שלו (15 מתוך 60; כרטיס חייל מצוות אחר = לא נמצא; כתיבה לצוות אחר נדחית ולא משאירה עקבות). צופה קורא את כל הקורס, כל כתיבה = FORBIDDEN, ובנוסף השרת מחזיר מצב אחורה (defense in depth). שינוי היקף/השבתה מנתקים sessions מיד; ההיקף החדש לא מרחיב בשקט.
- **שמירת נתונים:** מצב המנוע (חניכים, נוכחות וכו') נשמר בקובץ מוצפן AES-256-GCM (אטומי, שרשרת audit), שורד התנתקות/כניסה מחדש **ואתחול שרת**; אין שימוש חוזר במזהים אחרי אתחול. גיבוי מוצפן + שחזור fail-closed (שינוי/קטיעה נדחים, sessions מבוטלים אחרי שחזור).
- **ממשק:** אותו UI קיים (4 לשוניות, RTL) מחובר לשרת: מסך כניסה/בקשת גישה, "משתמשים ואישורי גישה" (אישור/דחייה/השבתה) תחת "עוד", התנתקות, באנר "צפייה בלבד", הסתרת כפתורי הוספה שאינם מורשים. נבדק ב-320/360/390/414 לשלושת התפקידים (אין גלישה, יעדי מגע ≥44px, ללא iframe, ללא PIN/טלפון/שמות באחסון הדפדפן).

## מה לא נטען (גבולות)
- **אין אימות בעלות על מספר הטלפון.** בסביבה זו מספר הטלפון הוא מזהה בלבד; אין SMS ואין ספק מאושר. אסור להציג זאת כאימות זהות.
- PIN בן 4 ספרות אינו מספיק לבדו מול נתונים אמיתיים (נדרש גורם שני/אימות מכשיר).
- Google (Drive/OCR/PDF) לא מחובר — פעולות שדורשות זאת מחזירות NOT_CONNECTED אמיתי, לא הצלחה מדומה (ראו ledger).
- תהליך יחיד + קובץ מוצפן: ריבוי מופעים/זמינות דורשים מסד נתונים טרנזקציוני. סודות מקומיים אינם מאגר סודות.

## חסמים לפריסה ב-URL פרטי, ומה סוגר אותם
| חסם | מה סוגר |
|---|---|
| אין מארח/דומיין/תעודה בסביבת הפיתוח | החלטת בעל המוצר+אבטחת מידע על מארח פרטי (VPN/IP מותר), תעודת TLS אמיתית, הרצת `test_server.js` שם |
| מאגר סודות וסבב מפתחות | מאגר סודות מאושר (pepper, מפתח אחסון, bootstrap) |
| אימות טלפון אמיתי | ספק SMS/OTP מאושר + החלטה על גורם שני |
| מסד נתונים עמיד/רב-מופעי | אישור מסד נתונים פרטי (החלפת `store.js`) |
| סקירת אבטחת מידע עצמאית | סקירה + pen-test על השרת |
| אישור go-live | חתימת בעל המוצר ואבטחת מידע לפני כל נתון אמיתי |
