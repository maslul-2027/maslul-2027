# מדריך בדיקת קבלה לבעלים — דמו סינתטי (עמוד אחד)

**כתובת חיה:** https://maslul-2027.github.io/maslul-2027/  
**גרסה:** `7a81b0794a83053c2d2db5ac217507c56cda44a5` (main אחרי #83). לא מתקינים כלום; פותחים בדפדפן בטלפון.  
כל הנתונים סינתטיים. הנתונים נשמרים **בדפדפן הזה בלבד** (לא בשרת ולא בין מכשירים). אל תנקו נתוני אתר באמצע הבדיקה. אין צורך באיפוס; הכפתור "איפוס הדגמה" שומר קודם עותק אחד בלבד שאפשר לשחזר.

## 1. מסע עם שני חסרים → עריכה אחרי שמירה
1. **בית** ← "מסע חדש". מלאו תאריך ומיקום, וסמנו **שני** חניכים בשלב "חסרים". התצוגה "סיכום" בתחתית מתעדכנת עם השמות.
2. "שמירה". **צפוי:** חוזרים לרשימת המסעות, והמסע מופיע עם "חסרים 2".
3. הקישו על כרטיס המסע. **צפוי:** נפתחת רשימת המשתתפים עם "חסרים 2".
4. על חניך חסר: "שינוי נוכחות" ← נוכח ← סיבה ← "שמירת שינוי". **צפוי:** "חסרים 1".
5. רעננו את הדף ופתחו שוב את המסע. **צפוי:** עדיין חסר אחד, מסע אחד, ללא כפילויות. 
*(ראיה אוטומטית: `scripts/e2e_native_marches.js`, צילומים: `docs/owner_acceptance/`)*

## 2. אירוע נוכחות רגיל
**בית** ← "אירוע נוכחות חדש" ← תאריך וסוג, סימון חסרים ← שמירה. פתיחה מכרטיס האירוע ושינוי נוכחות עובדים כמו במסע, והשינוי נשאר אחרי רענון.
*(ראיה: `e2e_native_acceptance.js`, צילום `event-edited-one-absent.png`)*

## 3. משימות וישיבות
- לשונית **משימות** ← כפתור `+` ← כותרת ← "שמירה". המשימה מופיעה מיד ונשארת אחרי רענון.
- **ישיבות**: "סיכום ישיבה חדש", נושא, שורות משימה (`+` או Enter מוסיפים שורה) ← שמירה. הישיבה והמשימות מופיעות פעם אחת.

## 4. חניך וכש״ג
- **חניכים** ← "+ הוספת חניך" ← שם ומספר אישי סינתטי ← שמירה. החניך מופיע ברשימה גם אחרי רענון.
- **כש״ג**: הזנת מבחן **רגיל** בלבד. טבלאות הניקוד הן DRAFT ואינן מאושרות מקצועית; אין להסיק מהן ציון רשמי.

## 5. מה לא עובד בדמו (במכוון, ולא מוצג כעובד)
- **ייצוא PDF / Excel, גיבוי ושחזור קבצים, העלאת מסמכים:** דורשים שרת מאובטח. בדמו תופיע ההודעה "טרם חובר להדגמה". הם נבדקו רק מול שרת HTTPS מקומי.
- **OCR, Drive/Google:** לא מחוברים.
- **איפוס/שחזור:** "עוד" ← "איפוס הדגמה": נשמר עותק יחיד בדפדפן; "שחזור לפני האיפוס האחרון" מחזיר אותו; "ייצוא נתוני הדגמה לקובץ" שומר לטווח ארוך.
- **מפקד:** נבדק כתפקיד מצומצם: רואה את התחום שלו בלבד ויכול רק **לבקש** תיקון.

## מה הוכח אוטומטית ומה לא
- **הוכח (Chromium אוטומטי, חיקוי מסך 320/360/390/414 ו-200% זום):** שמירה, עריכה אחרי שמירה ורענון (מסע ואירוע), לחיצה כפולה, מפקד שרק מבקש תיקון, היקף צוות, אופליין, מקלדת ותנועה מופחתת, וכן **יעדי מגע 44×44** בכל פקד אינטראקטיבי במסלולים (בית, טפסי מסע/אירוע, דיאלוג משתתפים ועריכה, משימה מהירה, עורך ישיבה, חניך חדש, מפקד ובקשת תיקון). פקד תיבת סימון נספר יחד עם התווית שלו.
- **תוקן:** שורות רשימת "חסרים" (ובחירת קורסים למפקד) היו קטנות מ-44px; כעת כל השורה היא אזור לחיצה בגובה 44px.
- **לא נבדק (NOT_RUN):** iPhone אמיתי (Safari), VoiceOver, ומכשיר פיזי של הבעלים. חיקוי Chromium אינו מחליף אותם.
