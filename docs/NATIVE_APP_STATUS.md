## Batch 6 (Issue #55) — truthful evidence model
**Ledger columns now separate evidence.** The app tags every call: calls made by the app's own UI code vs calls made through the test hook `window.__app.api` ("direct"). `PASS_SYNTH_E2E` now means *at least one successful UI-originated call* in a browser run; routes that only ever succeeded through the hook are `API_ONLY_NOT_UI`. `scripts/check_route_ledger.js` fails the build if a PASS row has no UI-originated success. Secured TEST E2E = NOT_RUN and deployed = NO for every row (unchanged).
Result (corrected after QA review of PR #59): PASS_SYNTH_E2E **142** (= routes with ≥1 successful UI-origin call; includes calls the app makes automatically on render, so it is NOT click proof) · of these **interaction_verified 139** (a successful UI-origin call that began ≤1.5 s after a *trusted* browser input event — real click/type/select/keypress — a machine-correlated gesture, not a semantic proof; E2E scripts additionally read state back) · POLICY_BLOCKED 1 (`dash.trends`, see below) · API_ONLY_NOT_UI 0 · IMPLEMENTED_NOT_E2E 0 · BLOCKED_NOT_CONNECTED 11 · NOT_IMPLEMENTED 20 (sum 174). The earlier statement of 143 'UI-verified' routes was inflated wording and is withdrawn; the CI gate now fails if `interaction_verified` exceeds PASS, lacks a gesture-correlated call, or disagrees with the summary.

**New native flows (click-tested in `scripts/e2e_native_batch6.js`, 29 checks):** fitness test-type editor (weights must total 100, active, pull-up rule; reason required; saved scores never recomputed implicitly), scoring-version sheet (draft-only row edit and table add; approved/superseded versions immutable), explicit per-record recompute, exam pass score, navigation group summary, readiness action queue, course dashboard (overview, department/team groups, per-soldier trends, compare 2–10 courses with <5 suppression), meeting detail + task detail, meeting audit-gap repair, emergency-contact orphan preview/cleanup (counts only), unified private file on the soldier card, admin "show cancelled records" toggle (so `record.restore` is reachable), shared-note cancel.
**Server change (additive, flagged for review):** `fitness.versions` accepts optional `rowsFor` (version id of the same course, admin `config.edit` gate) and then also returns that version's table rows so `fitness.editRow` can target a row id; `src/` manifest pin `tests/src_manifest_dev62.txt` regenerated.
**Fixes found while testing:** alert rows showed a generic title (now topic + reason), internal tokens (`DRAFT`, `Fitness.approve`) leaked in the draft-source note (localized), cancelled shared notes disappeared logic (now shown struck-through), reason dialogs left the parent dialog open.
**Synthetic fixtures (honest disclosure):** `alerts.handle`, `forms.review` and `meetings.auditRepair` are click-tested on rows injected into the synthetic browser store (the synthetic data has no triggering rule / public form submission / audit gap); the click path and server decision are real, the precondition is a fixture.
**Analytics privacy (PR #59 QA blockers 1–2):** the per-soldier 'מגמות לחניך' section was removed from the dashboard — the owner charter (`docs/OWNER_CURRENT_CHARTER_2026-11-20.md`) allows group-level analytics only. `dash.trends` is classified **POLICY_BLOCKED / NOT_EXPOSED_BY_DESIGN**: the backend route is preserved for an owner-approved disposition, no native screen calls it, and it is NOT counted as completed. Course overview for N<5 renders only a suppression notice (no counts/metrics); group rows that are suppressed (small group or complementary suppression) render 'מוסתר' with no number; compare-courses shows suppressed courses without numbers. Click-driven tests: N=3 course, a 5/2 team split with a suppressed row, an allowed N≥5 contrast, compare with a suppressed course; assertions forbid `undefined/null/NaN` and counts in suppressed rows.
**Engine bug found and fixed:** the persisted-store id counter regex lost its backslash in the generated engine, so after a reload new records could reuse an existing `id-N` (a new course collided with the demo course and a commander gained access to it). Fixed in `scripts/build_native_app.js`; regression covered by the foreign-course test.

**Not in this batch:** the 20 NOT_IMPLEMENTED routes (reports.build, import.*, docs.*, ocr.*, ai.*, backup.plan, migration.run) = Batch 7 (#56); the 11 adapter-blocked routes stay BLOCKED_NOT_CONNECTED.
