## 2. חזון לא ניתן לפשרה
**אפליקציה אחת, מהירה, מהנה, נגישה ואינטואיטיבית, שקל למפקד להבין ללא הדרכה — כמו הדוגמה הראשונה.** אין "אפליקציה בתוך אפליקציה", iframe, פיצול מאגרי נתונים, ריבוי תפריטים מעייף, חזרה למעטפת ה-Apps Script הישנה או הסתפקות בדמו שנראה טוב אך אינו עושה דבר. אין לוותר על תכונה מקורית לטובת פשטות; פשטות נוצרת באמצעות ניווט הדרגתי ותכנון תהליכים, לא באמצעות מחיקת יכולות.

**מקור עיצוב הזהב שאסור לפרש מחדש:** PR #10, commit a2f70692d0b6fe112cdc38a3f03d2ca799e46e36, הקובץ preview/index.html בענף feature/iphone-pwa-preview. מבנה: לוגו MASLUL 2027, hero כהה #15242b, רקע #f6f8f9, טורקיז #007f83 ו-CTA #04a6a4, כרטיסים לבנים ברדיוס 17px, 4 לשוניות **בית / חניכים / מעקבים / עוד**, RTL, חיפוש מיידי, KPI אמיתיים ופעולה ברורה אחת. לשמר חוויית iPhone גם עם כל המודולים; כל מסך הוא חלק אורגני מאותה שפה. אין נתוני KPI פיקטיביים.

**איכות שימוש:** תהליכים שכיחים ב-3 צעדים ברורים לכל היותר כשאפשר; חיפוש כולל לפי הרשאה; אחרונים ומועדפים; פעולה הבאה; טפסים בהדרגה; מצבי טעינה/ריק/שגיאה/אישור שרת; אישור מחיקה; גודל מטרה >=44px; נגישות מקלדת וקורא מסך; RTL; reduced motion; תמיכה ב-320–1440px ללא גלילה אופקית כללית; זמני תגובה מדודים ולא מומצאים.

## 3. היקף פונקציונלי מלא
היקף הבסיס הוא **174 פעולות API ב-39 קבוצות** ב-main/docs/capability-inventory.json, בתוספת מסכים ודרישות מארבע שיחות הפרויקט שקיימות בגרסאות קוד אחרות אך לא ברשימת ה-API. החלוקה: קורסים ומבנה; משתמשים/מפקדים/שיוכים; חניכים וכרטיס אישי מלא; קרוב חירום אחד לפי סכמה; נוכחות; כש"ג וכל טבלאות הניקוד; מבחנים א/ב/ג; ניווטים; קליעה; מסעות; כשירות; הסמכות; אירועים והערכות; הערות ומעקבים; תזכורות ומשימות/ישיבות; התראות; מועדפים; דשבורד ואנליטיקה קבוצתית; דוחות וייצוא; ייבוא; טפסים; מסמכים; OCR כטיוטה; עוזר קיים; הגדרות; audit; גיבוי/שחזור/מיגרציה/Preflight.

**ללא מחיקה שקטה:** לכל פעולה נרשמים URI/שם, מקור, מסך משתמש, הרשאת תפקיד והיקף, שדות קלט/פלט, מצב backend, UI מחובר, בדיקת הרשאה שלילית, בדיקת כתיבה/קריאה, מצב deploy, ראיות וקישור בדיקה. "קיים בשרת" **אינו** "עובד באפליקציה". רק חלופה שקולה שאושרה במפורש יכולה להחליף מימוש; ביטול דורש אישור בעל המוצר.

**כללים שאינם משתנים בלי אישור:** D1–D8 ו-N1–N7 בענף המקור; ניקוד רק מטבלאות המקור, תוצאה אחרונה בכש"ג, out_of_range לבדיקה, חסר אינו אפס, na לפי סוג, אין pass/fail שלא הוגדר, אין שינוי אוטומטי של ציונים שמורים; הרשאות צד שרת; דוחות מלאים/Excel/PDF למנהל בלבד ותצוגה מוגבלת למפקדים. אנליטיקה **קבוצתית בלבד**, N≥5 עם הסתרת קבוצות קטנות, ללא שמות/מזהים/תרשימי scatter/radar אישיים. כרטיס חניך תפעולי מורשה אינו דוח אנליטיקה.

## 4. ארכיטקטורה: מה כבר יש ומה צריך להשלים

- קוד Apps Script מהענף claude/import-r5-2-16-4-4-final ומנוע הסימולציה הם baseline פונקציונלי חשוב; אין להכניס אותם למוצר כסרגלי UI ישנים או להניח שסימולציה = אישור אבטחה.

- חזון ההתחברות שאושר: הרשמת משתמש בשם מלא + טלפון + PIN בן 4 ספרות, אישור מנהל חד־פעמי, שיוך תפקיד/קורס/מחלקה/צוות, owner read-only, ללא חובת Gmail למפקדים. PIN לבדו אינו מספיק: אימות זהות, hash מאובטח, הגבלת קצב/נעילות, sessions עם תפוגה וביטול, audit, בידוד קורס והגנת IDOR/CSRF.
- בחירת backend/אחסון פרטי, דרישות שיתוף, הרשאות, עלויות, מיקום נתונים וספקים חיצוניים דורשים בדיקה ואישורים; אין לבחור/לחבר לנתוני אמת עצמאית. Google Forms נועד לעדכון עצמי של חניכים בלבד לפי ההחלטה העדכנית, עם review ואימות.

**אישור דוגמה:** המנהל רשאי להעלות לבעלים צילום מסך/הדגמה לאישור, ובעל המוצר אינו חייב לאשר חלופה עיצובית שאינה זהה לדוגמה הראשונה. אין להשתמש בצילומי אבטיפוס/נתוני אמת בדמו ציבורי. עד קבלת אישור לשינוי חזותי **אין לבצע החלפת עיצוב רוחבית**; עבודת backend ו-QA יכולה להמשיך בלי להמתין.

**דיווח אפקטיבי:** לא מציפים הודעות "אני עובד" ריקות. כל עדכון מציין: PR, commit SHA, URL פועל או לא, מה השתנה בעין, אילו בדיקות הורצו והיכן, סטטוס כל היכולות, חוסמים ומה נדרש מהבעלים. אין לסמן פעולה שנוספה רק למיפוי כ"מוכנה". המנהל מודיע בכל פעם שנתן לקלוד משימה, כי ללא הפעלה מפורשת קלוד אינו מתחיל מעצמו.

## 7. שערי שחרור קשיחים
**L0 — דמו סינתטי ציבורי:** מותר רק נתונים מומצאים, קוד ציבורי ללא סודות, URL, בדיקות דפדפן, עיצוב מאושר. לא מיועד לשמירת נתונים פרטיים.  
**L1 — פיילוט סינתטי מאובטח:** backend פרטי, אחסון מתמיד, הזדהות/הרשאות אמיתיות, רישום פעולות, גיבוי, בדיקות רב-משתמשיות ורשת; מותר רק TEST מומצא.  
**L2 — שימוש בנתוני אמת:** בנוסף לכל L1 ו-174 parity מלא: **אישור אבטחת מידע/ארגוני כתוב על נתונים, שירותי ענן וספקים; בדיקות פרטיות והרשאות; backup/restore; בדיקות מכשיר; אישור מפורש של בעל המוצר למעבר לנתוני אמת ופריסה.** אם חסר אחד מהשערים, ההחלטה היא NO-GO לנתוני אמת. המנהל ו-Claude אינם רשאים לעקוף זאת בשם דחיפות.

**Go/No-Go להיום נקבע רק לפי L2**. המנהל מוסר לבעלים טבלה ברורה של PASS / FAIL / BLOCKED / NOT RUN עם ראיה לכל שורה ועם המינימום הממשי הנדרש ממנו להשלים חסמים. אין אישור מכללא.

## 8. טיפול במחלוקות ובהחמצת יעד
1. בעל המוצר מכריע בכל מחלוקת מוצר/עיצוב/מדיניות; המנהל מתעד את ההחלטה ומעביר למפתח.
