# מדריך הקמת סביבת Staging — למשתמש לא טכני

> **לפני שמתחילים:** המדריך הוא תכנון. **לא בוצע דבר מכל מה שכתוב כאן** (לא נוצרו חשבונות, לא התבקשו הרשאות, לא בוצעה פריסה). המטרה: סביבת בדיקות **מבודדת**, עם **נתוני דמה בלבד**, שלא נוגעת בשום מידע אמיתי. אם משהו לא מתנהג כמתואר — **עוצרים, מצלמים, ומדווחים**; לא מנסים "לתקן" בעצמכם (ראו `STAGING_ISSUE_PROCEDURE.md`).

## חלק א׳ — מי עושה מה
| מי | מה |
|---|---|
| **אתה (בעל המוצר)** | להחליט, להריץ את הקוד, לבדוק, לתעד |
| **מנהל Google Workspace** | ליצור את הסביבה והחשבונות ולאשר הגדרות ארגון |
| **אבטחת מידע** (אם הארגון דורש) | לאשר את ההרצה |
אתה לא משנה הגדרות ארגון. אם משהו נחסם ע"י הארגון — מבקשים ממנהל ה-Workspace, לא עוקפים.

## חלק ב׳ — מה צריך להיות מוכן לפני שמתחילים (בדוק לכל שורה "כן/לא")
1. החלטה כתובה שהבדיקה תתבצע ב-**Google Workspace** (לא Gmail רגיל). *סיבה: המערכת מזהה משתמשים לפי כתובת האימייל שלהם, וב-Gmail רגיל המפקדים לא יזוהו, ולכן אי אפשר לבדוק אותם.*
2. סביבת Workspace **מבודדת** לבדיקות (דומיין או יחידה ארגונית נפרדת) — ללא נתוני ייצור.
3. **שמונה חשבונות Google** (ראו חלק ג׳), שנוצרו ע"י מנהל ה-Workspace.
4. אישור מנהל ה-Workspace שמותר: להריץ Apps Script, ליצור אפליקציית Web ולפרוס אותה **לדומיין בלבד**, ולאשר 5 הרשאות (חלק ו׳).
5. אישור אבטחת מידע, אם נדרש אצלכם.
6. *(אינו תנאי להתחלה)* קישור **מילוי** של טופס Google Forms **לדמה** (מסתיים ב-`viewform`) — נדרש **רק** לבדיקה G18(א). אם אין לך, אל תנחש; בקש מהמנהל ליצור טופס ריק ולשלוח לך את הקישור. בלעדיו G18(א) נשאר חסום, וכל שאר הבדיקות — כולל G18(ב) — ממשיכות.
7. מחשב (לא טלפון) עם Chrome; לבדיקת נייד — טלפון iPhone וטלפון Android.
8. נתוני דמה: 12 חיילי דמה קיימים (`staging_demo/soldiers_demo.tsv`); ל-60/300 חיילים, ל-20 בקשות תיקון ולבקשה ישנה **עדיין אין** — **חסום, ממתין להחלטתך** (`STAGING_EXECUTION_PLAN.md` C-10, D-5). אין להמציא נתונים.
9. ה-ZIP של התוכנה — **אימות SHA-256 שלו מספיק כדי להתחיל**. **כדי ש-G01 יסתיים ב-PASS** נדרשים גם: `src_manifest_dev4.txt` (כלול בחבילה זו; סכום הבדיקה שלו עצמו = טביעת האצבע `32de95b6…8a8f`, כך שניתן לאמת שהמניפסט לא שונה), ואפשרות **להוריד את תוכן הפרויקט מ-Apps Script ולהשוות אותו** (מחשב עם Node.js + `@google/clasp`, הפעלת Apps Script API לחשבון ADMIN, והסכמת OAuth — ראו `STAGING_EXECUTION_PLAN.md` §2ג, P16, D-9). בלי אלה G01 = BLOCKED.
10. תיקייה בטוחה לשמירת צילומי מסך (ראיות) + קובץ `STAGING_RESULTS.md` שתיצור בעצמך (עמודות: ID · תאריך/שעה · חשבון ותפקיד · גרסה · PASS/FAIL/BLOCKED/NOT_RUN · קובץ ראיה · הערות).
אם אחת מהשורות 1–5, 7 או 10 היא "לא" — לא מתחילים; מדווחים לפי `STAGING_EXECUTION_PLAN.md` §3. שורות 6 ו-8 אינן תנאי התחלה (חוסמות רק את G18(א), את G19 ואת G11 צעד 5). שורה 9: ה-ZIP מספיק להתחלה; המניפסט והורדת התוכן נדרשים לסגירת G01 כ-PASS.

## חלק ג׳ — שמונת החשבונות (מנהל ה-Workspace יוצר; אתה מקבל כתובות וסיסמאות בצורה מאובטחת)
| שם | מי זה | חשוב לדעת |
|---|---|---|
| **ADMIN** | המנהל והבעלים של הפרויקט | כתובתו תוזן כ-`ADMIN_EMAIL` באותיות קטנות |
| **CMD-A** | מפקד צוות א׳ בקורס 1 (`צוות 1 (זמני)`) | |
| **CMD-B** | מפקד צוות ב׳ בקורס 1 (`צוות 2 (זמני)`) | |
| **CMD-C2** | מפקד בקורס 2 בלבד | |
| **CMD-NONE** | מפקד בקורס 1 **בלי שיוך** | |
| **STRANGER** | משתמש בדומיין שלא רשום במערכת | לא מוסיפים אותו למערכת |
| **INACTIVE** | משתמש שנרשם ואז הושבת **במערכת** | **חשבון ה-Google שלו נשאר פעיל ומתחבר רגיל. אל תשבית אותו ב-Google.** רק ברשומת Course Tracker מסמנים `active=false`. הבדיקה: המערכת חוסמת אותו גם ש-Google מאפשר לו להיכנס |
| **OUTSIDE** | חשבון מחוץ לדומיין | |
לכל חשבון: שם סמלי, **לא שם אמיתי של אדם**. לפתוח כל חשבון בחלון דפדפן פרטי נפרד (או פרופיל נפרד) כדי לא להתבלבל.

## חלק ד׳ — סדר ההקמה והבדיקות (מבצע: אתה, על המחשב; עדיין כלום לא בוצע)
> **כללי סדר:** כל שלב מתחיל רק אחרי שהשלבים שלפניו הסתיימו (PASS או תועדו). הסדר זהה לסדר המחייב ב-`STAGING_TEST_EXECUTION_TABLE.md` §2. כל תוצאה — בקובץ התוצאות. כשל — `STAGING_ISSUE_PROCEDURE.md`.

**שלב 1 — פרויקט חדש (G01)**
1. התחבר כ-**ADMIN** (פרופיל נפרד).
2. היכנס ל-Google Apps Script ופתח **פרויקט חדש** בשם `CourseTracker-STAGING`.
3. בהגדרות הפרויקט הפעל "Show appsscript.json manifest file in editor".
4. **שלמות ה-ZIP (מספיקה להתחלה):** אמת SHA-256 של ה-ZIP (`edcc0aabe51f12643bc060f27191e525ab2af3564b30387a76900d2fdf7b0f75`). אם אינך יודע איך — בקש עזרה טכנית. שונה → עצור.
5. **זהות קבצי המקור (חובה ל-PASS):** חלץ את ה-ZIP לתיקייה ריקה `verify_src/src/`, שים לידה את `src_manifest_dev4.txt` והרץ `sha256sum -c src_manifest_dev4.txt` — צפוי 41 שורות `OK`; ובדוק שאין קבצים עודפים (פקודת `comm` בטבלת הביצוע G01 צעד 2). **אם אין מניפסט או אי אפשר להשוות — G01 = BLOCKED** (לא PASS). אחרי ההשוואה: העתק את **41** הקבצים מתיקיית `src/`: 38 קבצי `.gs`, `Index.html`, `FormPage.html` (השמות בדיוק `Index` ו-`FormPage`), ואת `appsscript.json`. **מחק או דרוס את קובץ ברירת המחדל** שנוצר עם הפרויקט החדש. **אל תשנה תוכן.** אל תעתיק `tests/` או `docs/`. **העתקה מוצלחת אינה הוכחה שהתוכן זהה.**
6. אם העורך דוחה את המניפסט — עצור, צלם את השגיאה, דווח. אל תתקן. **אימות התוכן בפרויקט (חובה ל-PASS; אסור להפעיל `clasp` או Apps Script API לפני החלטה מפורשת שלך D-9 — בלעדיה G01 = BLOCKED):** בלי לערוך כלום בפרויקט, הורד את תוכנו לתיקייה ריקה `verify_project/src/` (`clasp pull`; או Apps Script API — `STAGING_EXECUTION_PLAN.md` §2ג), הרץ שוב `sha256sum -c src_manifest_dev4.txt` ובדיקת העודפים, ושמור את הפלט המלא. צפוי 41 `OK`. כל הבדל, או אי-יכולת להוריד → עצור (FAIL / BLOCKED לפי טבלת הביצוע G01); אל תתקן "על הדרך". אחרי האימות — ללא עריכות; צור את הפריסה (G06) מיד.

**שלב 2 — הגדרת מנהל**
7. הגדרות הפרויקט ← Script Properties ← הוסף `ADMIN_EMAIL` = כתובת ADMIN, **באותיות קטנות, בדיוק כפי שהיא**.
8. `PERSONAL_FORM_URL` **לא** מוגדר עכשיו — רק ב-G18(א), ורק כשסופק לך קישור `viewform`.

**שלב 3 — התקנה ראשונה (G02)**
9. בעורך בחר `setupDatabase` ולחץ Run.
10. יופיע חלון הרשאות. "Google hasn't verified this app" **צפוי**; אם הארגון מאפשר — Advanced ← המשך. ההרשאות: חלק ו׳. הרשאה שלא ברשימה — עצור ודווח. צלם את המסך.
11. צפוי: נוצרים **שני גיליונות**. **אל תשתף אותם.** צלם.
12. הודעה "רק למנהל המערכת" כשאתה ADMIN **אינה תוצאה תקינה** ואינה PASS. קודם השווה: הכתובת המדויקת של החשבון המחובר בעורך מול `ADMIN_EMAIL` (אותיות קטנות, ללא רווחים, כתובת ראשית). שונות → תקן את **המאפיין בלבד**, תעד והרץ שוב. זהות והחסימה נמשכת → **FAIL**: עצור, צלם, דווח; לא לשנות קוד ולא להחליש את המגן. חסימת **משתמש אחר** (לא ADMIN) היא התנהגות תקינה — היא נבדקת ב-G03.

**שלב 4 — פריסה (G06; דורש אישור מנהל WS)**
13. Deploy ← New deployment ← Web app. **Execute as: Me. Who has access: Anyone within <שם הדומיין>.** לעולם לא "Anyone".
14. שמור את כתובת ה-`/exec` (אל תפיץ). פתח כ-ADMIN; צפוי מסך "מצב קורס" (גרסה `1.0.6-b7b8-r3-product-dev4`).

**שלב 5 — קורסים ומשתמשים (G05 ואז G04; מתוך האפליקציה — דורש שלב 4)**
15. צור **"קורס בדיקה 1"** ו-**"קורס בדיקה 2"** (מסך "קורסים ומשתמשים"). (לא `createFirstCourse` מהעורך — C-3.) כל קורס נוצר עם 2 מחלקות × 2 צוותים: `צוות 1 (זמני)`…`צוות 4 (זמני)` — אם השמות שונים, עצור ודווח (אל תשנה שמות).
16. הוסף משתמשים: CMD-A, CMD-B, CMD-C2, CMD-NONE, INACTIVE. **לא** מוסיפים STRANGER.
17. שייך: CMD-A→`צוות 1 (זמני)`; CMD-B→`צוות 2 (זמני)`; CMD-C2→קורס 2; CMD-NONE ללא שיוך. לכל שיוך סיבה.
18. סמן את INACTIVE כלא פעיל **במערכת בלבד** (לא ב-Google). אי אפשר להשבית את המשתמש שלך (ADMIN).

**שלב 6 — בדיקות אבטחה ראשונות (G03, G07; דורשות שלב 5)**
19. G03 — כ-CMD-A מה-Console. **אם קריאה כלשהי הצליחה — עוצרים (S1).**
20. G07 — STRANGER, INACTIVE, OUTSIDE, ADMIN (כולל הוכחה ש-INACTIVE מתחבר ל-Google).

**שלב 7 — נתוני דמה והיקף (G10, אחריו G08, G09, G11)**
21. G10 — כשקורס 1 נבחר: ADMIN מייבא את 12 חיילי הדמה (מסך "ייבוא Excel" ← הדבקה של `soldiers_demo.tsv` ← תצוגה מקדימה ← אישור; צפוי 3 חיילים בכל אחד מארבעת הצוותים) ויוצר חייל דמה אחד ידנית בקורס 2; CMD-A מזין תוצאת ניווט לחייל ב-`צוות 1 (זמני)`.
22. G08 ← G09 ← G11. **G11 צעד 5 (בקשה ישנה) חסום עד אספקת נתון — לא ממציאים.**

**שלב 8 — גיבוי (G12) ומיד אחריו התקנת הטריגר (G14 שלב א׳)**
23. G12 — גיבוי ידני ואימות.
24. **רק אחרי ש-G12 הושלם ב-PASS** (ובלי S1 פתוח או חסם של מנהל WS/אבטחת מידע על התקנת טריגר): `installDailyTrigger` מהעורך; בדף Triggers — טריגר אחד על `dailyJob_`. תעד תאריך/שעה. **זה עדיין לא PASS.** אל תנסה להפעיל את `dailyJob_` ידנית (פרטית); הפעלה ידנית = `runDailyJobNow` (G15).
25. **מכאן עד הריצה המתוזמנת הראשונה (עד יממה) ממשיכים בשלב 9.** אל תריץ G15/G16 בין 01:45 ל-03:15.

**שלב 9 — המשך הבדיקות בזמן ההמתנה**
26. לפי הסדר: G13, G17, G20, G21, G23, G15, G16, G18, G19 (חסום), G22, G24.

**שלב 10 — אימות הריצה המתוזמנת (G14 שלב ב׳)**
27. אחרי הריצה המתוזמנת הראשונה: `Executions` (רשומת Time-driven של `dailyJob_`), `BackupJobs` (שורה `daily`), Preflight `trigger.daily`. שורת `BackupJobs` לבדה לא מספיקה.

**שלב 11 — אופציונלי:** G25 — רק אחרי שהוגדרו צעדים (C-13).

## חלק ה׳ — כללים שאסור לעבור
- נתוני דמה בלבד. אין שמות/מספרים/טלפונים אמיתיים.
- אין לשתף את הגיליונות או תיקיית הגיבויים. אין פריסה "Anyone".
- אין לשנות קוד, הרשאות Google/ארגון, ניקוד, משקלים, ספים או החלטות מוצר.
- אין לפרוס לייצור. המערכת אינה מוכנה להפעלה מבצעית.
- אין להעתיק קישורי טוקן לטופס חד-פעמי למשתמשים. הטופס מושבת אם G18(ב) נכשל.
- כישלון = מתעדים ועוצרים לפי הנוהל. לא "מתקנים".

## חלק ו׳ — ההרשאות שיבוקשו (ממניפסט הקוד)
| הרשאה | למה |
|---|---|

## חלק ז׳ — בסיום
ביטול הרשאות האפליקציה בחשבון, ביטול ההסכמה של כלי האימות (`clasp`) והסרת אישורי הכלי ותיקיות `verify_*` מהמחשב, מחיקת הטריגר והפריסה, ואיפוס/ניקוי סביבת הבדיקה לפי `STAGING_ENVIRONMENT.md` §9 (לאמת בעלות ושם לפני מחיקה; לא לרוקן אשפה כללית). לתעד מה נמחק ומה נשמר.
