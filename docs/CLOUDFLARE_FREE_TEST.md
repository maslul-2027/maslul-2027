# MASLUL — סביבת בדיקה משותפת על Cloudflare Workers Free + D1 Free

**סטטוס:** קוד + בדיקות בלבד. **לא נפרס, אין חשבון, לא נמזג, `main`/Pages ללא שינוי.** נתונים סינתטיים בלבד.
**עלות חוזרת:** 0 ₪ — אין כרטיס אשראי, אין SMS, אין שרת בתשלום, אין Google Apps Script.
**הקוד:** `cloudflare/free-shared-test/` (+ `scripts/build_cf_worker.js`, `native/cf_client.js`). **CI:** `.github/workflows/cloudflare-free-test.yml`.

## 1. מה נבנה
- אותו ממשק RTL של 4 הלשוניות (בסיס #90), מוגש כקבצים סטטיים; אותו מנוע אמיתי (`src/*.gs`) מקומפל בזמן בנייה לפונקציית ESM (בלי `eval`/`new Function`, אסור ב-Workers).
- נתונים מתמידים ב-D1: מסמכי JSON `rows(tbl,id,json)` + וקטור גרסאות לכל טבלה; כל בקשה טוענת רק את הטבלאות הנחוצות, מריצה את המנוע על עותק, ומבצעת **batch אטומי אחד** עם שער גרסאות (בקשות מקבילות → ניסיון חוזר, לא דריסה).
- היסטוריית ביקורת (`AuditLog`) append-only.
- **אין PIN ואין תפקיד שמגיע מהלקוח.** התפקיד/הצוות נקבעים בשרת מתוך הסשן בלבד.

## 2. זהות והרשאות (דורש אישור הבעלים — לא הוענק על ידי)
1. **הגדרה ראשונה:** אסימון `BOOTSTRAP_TOKEN` חד-פעמי (סוד ב-Cloudflare) → מנהל ראשון → קוד גישה + אפליקציית אימות (TOTP).
2. **בקשת גישה:** משתמש שולח שם+אימייל → המנהל מאשר במסך "הרשאות" ובוחר תפקיד/צוות/מחלקה → נוצר **קישור הצטרפות חד-פעמי** שהמנהל מעביר בעצמו.
3. **כניסה:** אימייל + קוד גישה (אחסון: HMAC עם `APP_SECRET`) + קוד TOTP (הסוד מוצפן AES-GCM, צעד משומש נדחה).
4. סשן: עוגיית `__Host-` HttpOnly Secure SameSite=Strict, CSRF לכל סשן + בדיקת Origin מדויקת, פקיעת סרק 60 דק׳ / מוחלטת 12 ש׳, נעילת חשבון + הגבלת קצב לפי IP, **ביטול מיידי** (הבקשה הבאה נכשלת).
5. **האימייל הוא מזהה שהמנהל מאשר — לא הוכחת בעלות על תיבת דואר** (אין שליחת מייל במסלול חינמי, וגם אין SMS). זו החלטה שדורשת אישור הבעלים/אבטחת מידע לפני שימוש מבצעי.
6. `workers.dev` ציבורי: הקליפה ציבורית אך **אין בה נתונים**; כל נתיב נתונים דורש סשן. אפשרות מומלצת בהמשך (חינמית): Cloudflare Access מעל הדומיין.

## 4. היתכנות מול מגבלות Free (מדידה מקומית — **לא** אכיפת Cloudflare)
מגבלות (מתיעוד Cloudflare הרשמי, נבדק 22.11.2026): Workers Free — 10ms CPU לבקשה, 100K בקשות/יום; D1 Free — 50 שאילתות לקריאה, 100KB לשאילתה, **1,000,000 בתים למחרוזת/פרמטר/שורה** (הקוד מוגבל ל-900KB לפרמטר), 100 פרמטרים; **5GB אחסון כולל לחשבון** (ומגבלת גודל למסד בודד 500MB בתוכנית Free לפי עמוד ה-Limits), 5M קריאות שורה ו-100K כתיבות שורה ליום; חריגה **נחסמת ואינה מחויבת**. (תיקון: בגרסה קודמת נכתב 500MB כמגבלת אחסון כוללת ו-2MB לפרמטר — שניהם לא מדויקים.)

|---|---|---|---|
| כניסה (קוד+TOTP+סשן) | 0.9 / 1.0 | 5 | — |
| בדיקת סשן | 0.3 / 0.2 | 1 | 1/0 |
| `soldiers.list` (60) | 3.2 / 0.9 | 3 | 75/0 |
| `marches.create` + סגל | 3.1 / 1.2 | 6 | 475/21 |
| `meetings.save` + משימה | 3.6 / 1.6 | 6 | 196/12 |
| `dash.home` (ללא מטמון) | 11.9 / 9.6 | 7 | 955/1 |
| `reports.preview` | 15.3 / 8.8 | 7 | 959/1 |
- מקסימום 14 שאילתות לבקשה (מגבלה 50); אתחול מודול ~90ms. חבילה ~200KB gz (מגבלה 3MB gz).
- **סיכון מוצהר:** `dash.home`/`reports.preview`/`soldiers.card` בהרצה קרה חורגים מ-10ms במדידה מקומית. מנגנוני הפחתה: מטמון תוצאה לכל משתמש עם וקטור גרסאות (`x-maslul-cache: hit` — לעולם לא מידע ישן מכתיבה אחרונה) + חימום באתחול. **מדידת CPU אמיתית ב-Cloudflare: NOT_RUN** — נדרש חשבון. אם יחרוג: ירידת איכות מבוקרת לנתיבים האלה בלבד, או החלפה לחלופה §7.
- **נפילה מבוקרת בחריגת מגבלה:** אם Cloudflare חוסם בקשה (חריגת CPU/עומס — תשובה 5xx/429 שאינה JSON) הלקוח מציג הודעה ברורה (קריאה: `PLATFORM_LIMIT` "נסו שוב או פתחו מסך קל יותר, אין צורך בשדרוג"; **כתיבה: `UNKNOWN_OUTCOME` "לא ניתן לאשר אם הפעולה נשמרה — רעננו ובדקו; שליחה חוזרת אינה יוצרת כפילות"**, כי ייתכן שהשרת כבר שמר לפני שהתשובה אבדה; מפתח האידמפוטנטיות נשמר לשליחה חוזרת בטוחה, 4 דקות, ומתאים לחלון השרת של 5 דקות) ולא מסך ריק; אין שדרוג ואין חיוב. מדידת CPU/D1 אמיתית — רק אחרי אישור חיבור, על נתונים סינתטיים.
- גידול `AuditLog`: כל קריאה של היסטוריה מלאה תגדל עם הזמן — מגבלה ידועה לבדיקה בלבד.

## 6. חיבור Cloudflare Free — מדריך לבעלים (בלי קוד, בלי טרמינל, בלי תשלום)
**אין "לחיצה אחת".** כפתור Deploy to Cloudflare דורש מאגר ציבורי ולכן לא מתאים (המאגר פרטי, הענף ייעודי). משתמשים ב-Workers Builds מתוך לוח הבקרה. כל מה שלהלן בלחיצות; הבעלים לא כותב קוד ולא מריץ פקודות.

### בקשת אישור (נשלחת לבעלים ול-IT/אבטחת מידע — כתובה כך שאפשר לענות "מאשר")
> **מאשר לחבר את מאגר GitHub הפרטי הקיים `maslul-2027/maslul-2027` לחשבון Cloudflare Free חדש, לצורך סביבת בדיקה סינתטית בלבד** (נתונים בדויים, בלי נתוני אמת, בלי כרטיס אשראי, בלי שירות בתשלום, בלי שינוי ב-main/Pages). זיהוי: אימייל שהמנהל מאשר + קוד גישה + אפליקציית אימות. שלב ההפעלה בפועל ובדיקת שני טלפונים — **באישור (GO) נפרד** אחרי החיבור.

### שלב א — חשבון וחיבור (פעולת הבעלים)
1. dash.cloudflare.com → Sign up עם אימייל. **תוכנית Free; לא מזינים כרטיס אשראי.** אם מוצגת בקשת תשלום/שדרוג — עוצרים ומדווחים.
2. Workers & Pages → Create → **Import a repository** (GitHub) → Install/Authorize → **Only select repositories** → לבחור רק `maslul-2027/maslul-2027`.
### שלב ב — הגדרת הבנייה (מתבצע בהכתבה, מסך משותף)
3. שם Worker: `maslul-test` (חייב להיות זהה ל-`name` ב-`wrangler.toml`). **Root directory: `cloudflare/free-shared-test`**.
4. **Production branch: `cloudflare/free-shared-test` — לא `main`.** (Settings → Build → Branch control.) **Builds for non-production branches: כבוי.** Build command: ברירת מחדל. Deploy command: `npx wrangler deploy` (ברירת מחדל).
5. כתובת: `https://maslul-test.<חשבון>.workers.dev` (HTTPS כברירת מחדל; ללא דומיין מותאם, ללא תשלום). גרסת wrangler נקבעת מ-`package.json` (≥ 4.45).
### שלב ג — מסד נתונים D1
6. **מסלול רגיל:** ההגדרה `DB` ללא מזהה ב-`wrangler.toml` גורמת ל-wrangler (4.45+, בטא) ליצור את המסד `maslul-test-db` בפריסה הראשונה ולקשור אותו כ-`DB`. **NOT_RUN עד חשבון אמיתי.**
7. **אם ההקצאה האוטומטית נכשלת (שגיאה בבנייה על D1/binding):** Storage & Databases → D1 SQL database → Create → שם `maslul-test-db` → Create. אחר כך Workers & Pages → `maslul-test` → Bindings → Add binding → D1 database → Variable name **`DB`** → המסד שנוצר → Deploy. הסכמה נוצרת על ידי ה-Worker בפנייה הראשונה (בלי מיגרציה ידנית).
### שלב ד — סודות האימות (הבעלים בלבד; לא בצ'אט, לא ב-GitHub, לא אצלי)
8. ליצור שני ערכים אקראיים של 40 תווים לפחות במחולל הסיסמאות של הבעלים (מנהל הסיסמאות בטלפון/דפדפן) ולשמור אותם שם.
9. Worker `maslul-test` → Settings → Variables and Secrets → Add → סוג **Secret** (לא Text): שם `APP_SECRET` + ערך ראשון; שם `BOOTSTRAP_TOKEN` + ערך שני → Deploy. לוודא בלשונית Deployments שנוצרה פריסה חדשה (אחרת Builds → Retry build).
### שלב ה — GO נפרד, ואז בדיקה
10. **רק אחרי GO מפורש:** הבעלים פותח את הכתובת בטלפון 1 → "הגדרה ראשונית" → שם/אימייל/`BOOTSTRAP_TOKEN` → אפליקציית אימות. טלפון 2: "בקשת גישה" → המנהל מאשר ומעביר קישור חד-פעמי → כניסה.
11. מדידות אחרי חיבור (נתונים סינתטיים בלבד): CPU אמיתי של Worker (לוח Metrics), מכסות D1 (Rows read/written, Storage), שגיאות 1102. חריגה = ירידת איכות מבוקרת, **לא שדרוג**.
**עצירה מיידית** על: בקשת כרטיס/תשלום, גישת GitHub לכל המאגרים, או כל נתון אמיתי. לא ממזגים ל-`main`, לא נוגעים ב-Pages.

## 6א. שחזור והתאוששות (Time Travel החינמי של D1)
| יכולת | מצב |
|---|---|
| **שחזור נקודתי עד 7 ימים אחורה** (לכל דקה), ברירת מחדל, ללא עלות, ללא R2 | קיים ב-Cloudflare לבסיסי נתונים בתשתית production; **NOT_RUN** עד שיש מסד אמיתי. מגבלה: 10 שחזורים ל-10 דקות. אינו נספר באחסון. |
| שחזור/גיבוי **מתוך האפליקציה** (כפתור) | **אין ואין בכוונה** — `backup.*` מחזיר 501 `NOT_CONNECTED`; שחזור הרסני לא יופעל אוטומטית ולא מאף משתמש/מנהל אפליקציה. |
| התאוששות מאסון **מחוץ לספק** | **אין** (Time Travel חי באותו חשבון Cloudflare). חלופה אופציונלית ללא עלות: ייצוא SQL ידני על ידי המפעיל (`wrangler d1 export` / לוח הבקרה) לקובץ מקומי מוצפן — לאחסון ארוך מ-7 ימים. נתוני פיילוט סינתטיים בלבד, לכן לא נבנה תהליך אוטומטי. |

**Runbook (מפעיל בלבד = בעל חשבון Cloudflare; לא תפקיד באפליקציה):**
1. להקפיא: לבקש מהמשתמשים להפסיק לעבוד (אפשר גם להשבית זמנית את ה-Worker מלוח הבקרה).
2. `wrangler d1 time-travel info DB` (או לוח הבקרה) — לרשום את ה-bookmark **הנוכחי** (זה כפתור ה-Undo).
3. לבחור דקה יעד (`--timestamp`) שקדמה לתקלה. **שחזור כותב על המסד החי** ומחזיר את כל הטבלאות — כולל משתמשים וסשנים.
4. `wrangler d1 time-travel restore DB --timestamp=...` (הכלי מציג bookmark קודם — לשמור).
5. **מיד אחרי:** להריץ `ops/post_restore.sql` (מבטל **את כל הסשנים**, מנקה מטמון ומגבלות קצב, רושם ביקורת). בלי השלב הזה סשן שבוטל אחרי נקודת היעד היה "חוזר לחיים". נבדק ב-S21 (סימולציה על ה-shim — לא על Cloudflare).
6. מנהל האפליקציה בודק מחדש את רשימת המשתמשים: משתמש שהוסר אחרי נקודת היעד עלול להיות פעיל שוב — להשבית ידנית. נתונים שנכתבו אחרי נקודת היעד **אבדו** (אין שחזור חלקי).
7. אם התברר שנבחרה נקודה שגויה — לחזור ל-bookmark משלב 2.

## 7. חלופה ב-0$ אם יתברר שאין היתכנות
Firebase Spark (Auth + Firestore + Hosting): אותו מודל אבטחה בצד שרת באמצעות כללי אבטחה; מגבלות: אימות טלפון/SMS אינו חינמי (נשארים עם אימייל), Cloud Functions דורשות Blaze (לכן הלוגיקה תעבור לצד לקוח + כללים — פחות הרשאות עדינות). לא נבנה כעת. **לא** חוזרים ל-GAS ולא ל-VPS בתשלום.
